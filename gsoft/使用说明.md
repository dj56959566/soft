# GitHub 批量删库工具 — 使用说明

版本：v2.0　更新：2026-11-14　仓库：djbadboy-56959566-qq-com/soft

> 一句话：这个工具帮你不用一个一个在网页上点，就能批量看、批量删、批量搬 GitHub 仓库。
> 双击 exe 就进中文菜单，启动时先问你要 Token，谁用问谁要。

---

## 1. 这是什么，能做什么

| 功能 | 说明 |
|---|---|
| 查看仓库清单 | 先选范围：个人仓库 / 组织仓库 / 全部，再列清单 |
| 勾选删除仓库 | 列清单后输序号勾选再删，不会一上来就删；一次可以选多个 |
| 移动合并仓库 | 把 A 仓库整个搬到 B 仓库的子目录下 |
| 归档仓库 | 代替删除，只读、可恢复 |
| 中文菜单 | 双击 exe 就进菜单，不用记命令 |
| 打包成 exe | 用仓库里的 GitHub Actions 自动打包，不用装 Python 也能跑 |

**删除是不可逆的。** 仓库删了，代码、Issues、PR、Wiki、Release 全没了，GitHub 也恢复不了。
删前工具会自动把完整清单备份到 `repos_list.txt`，删完写日志 `deleted_*.log`。
只想清理、不想丢东西，先用“归档”，不要直接删。

## 2. 下载：exe 还是 Python

### 方法 A：直接用 exe（推荐，不用装 Python）

1. 打开仓库主页：`https://github.com/djbadboy-56959566-qq-com/soft`
2. 右边“发行版”里找到最新版本（比如 `v2.0`），点进去
3. 下载里面的 `github-repo-cleaner-windows.zip`，解压得到 `github-repo-cleaner.exe`，放到一个空文件夹里，双击就能跑
4. 发行版里只保留最新 2 个版本，超过的会自动删掉，不用自己清理

> exe 是命令行工具，双击会弹出一个黑窗口，这就是菜单，不要关掉它。
> Windows Defender 有时会对 PyInstaller 打包的 exe 误报，点“更多信息 → 仍要运行”即可。
> Actions 页面里不再放附件，打包文件只在发行版里下载。

### 方法 B：用 Python 跑（适合 Serv00 / N1 / Linux / Mac）

```bash
# 需要 Python 3.8 以上，不用装任何依赖包
python3 clean_repos.py
```

## 3. 准备 Token：第一次用必须做

Token 就是一把钥匙，让工具能替你操作 GitHub。**谁用，启动时就问谁要，不用提前发给别人。**

### 3.1 去哪里建 Token

打开这个网址：

```
https://github.com/settings/tokens
```

路径：GitHub 头像 → Settings → 开发者设置 Developer settings → Personal access tokens → Tokens (classic) → Generate new token (classic)。

### 3.2 勾选哪几个权限

只勾这 3 个，多勾的也没关系：

- `repo`（读写仓库）
- `read:org`（扫组织仓库，在 `admin:org` 下面）
- `delete_repo`（删库）

备注可以写 `github-repo-cleaner.exe`，有效期选“无有效期”或者按你自己的习惯选。
点最下面的绿色按钮“生成令牌”，Token 只显示一次，马上复制好，关掉页面就再也看不到了。

### 3.3 用谁的 Token

- 谁跑这个 exe，就用谁自己的 Token。
- 要删哪个组织的库，就用在那个组织里有管理员 / Owner 权限的号的 Token，普通成员会报 403。
- 组织开了 SAML 保护，还要在 Token 页面点 Authorize 授权给那个组织。

### 3.4 粘贴 Token 的几种办法

黑窗口里左键是选中、右键才是粘贴，左键点一下粘贴不了，这是黑窗口本身的规矩，不是脚本的问题。

- **办法 1（最省事）：** 在浏览器里复制好 Token，回到黑窗口直接按回车，自动从剪贴板读取，不用粘贴。
- **办法 2：** 在黑窗口里按 `Ctrl+V` 粘贴后按回车。`Ctrl+V` 不灵就点窗口左上角图标 → 属性 → 选项 → 勾上“启用 Ctrl 键快捷方式”，以后 `Ctrl+V` 就能直接粘。
- **办法 3（粘贴实在不灵）：** 用记事本在 exe 旁边新建一个 `token.txt`，把 Token 粘贴进去保存，再运行 exe，它会自动读取，不用在黑窗口里粘贴。`token.txt` 只放你自己电脑上，千万别传到 GitHub 仓库里。

粘贴上去不显示也不怕：按回车后会显示“已收到 Token，共几位，开头 ghp_”，证明粘贴进来了，再去校验。校验通过后会自动清屏，Token 不会留在屏幕上，也不会保存到任何文件里。

还没建 Token 就在提示那里输 `1` 回车，帮你打开建 Token 的网页。

## 4. 运行 exe：一步一步照着做

### 4.1 启动

双击 `github-repo-cleaner.exe`，黑窗口里出现中文菜单。启动时先问你要 Token：

```
GitHub 批量删库工具 v2.0
第一步：先要你的 GitHub Token（谁用问谁要）。
Token 需要勾选这些权限：delete_repo（删库）+ read:org（扫组织）+ repo

去这里建 Token：
https://github.com/settings/tokens
（Classic 类型，Generate new token (classic)）
点不开就输 1 回车，帮你打开这个网页。
```

按上面第 3.4 节的办法把 Token 给它，校验通过会显示当前账号，比如 `Token 有效，当前账号：djkyc`，还会显示这个 Token 的权限范围。

Token 不对会告诉你是 401 还是 403，最多可以重输 3 次；输 `q` 退出。

### 4.2 主菜单

```
GitHub 批量删库工具 — 中文菜单
1. 查看仓库清单（只看不删，最安全）
2. 勾选删除仓库（列清单 → 输序号 → 输 y 两次确认）
3. 移动合并仓库（A 仓库搬到 B 仓库的子目录下）
4. 归档仓库（代替删除，可恢复）
0. 退出
```

输 `1-4` 选功能，输 `0` 退出。每做完一步都要按回车才回菜单，双击也不会一闪而过。

### 4.3 先选范围：个人还是组织

选 1、2、4 之前会先问你看哪个范围，每个范围单独一行，后面还显示有几个仓库，一眼就能分清：

```
先选看哪个范围

1. 个人仓库：djkyc（49 个仓库）

2. 组织仓库：djbadboy-56959566-qq-com（69 个仓库）

9. 全部：个人 + 所有组织

0. 返回菜单
```

输 `1` 只看你自己的，输 `2` 只看组织的（有几个组织就再选一个），输 `9` 看全部，输 `0` 回菜单。选完只列那个范围的仓库。

### 4.4 清单一页 10 个，可以翻页

清单一页显示 10 个，序号是全局序号，翻页后勾选还用这个号：

```
共 69 个仓库，第 1/7 页（一页 10 个）：
序号  仓库  可见性  *  更新  描述
1  djbadboy-56959566-qq-com/6.6onecloud  public  0  2025-12-13  ...
...

看完了吗？

输 q  结束浏览，去勾选要删除的仓库

输 n  下一页
输 p  上一页
输数字 跳到第几页（比如输 3 跳到第 3 页）
```

看完输 `q`，去勾选；还想翻页就输 `n` / `p` / 数字。已经是最后一页再输 `n` 会提醒你输 `q` 去勾选。

## 5. 菜单逐项怎么用

### 5.1 选 1：查看仓库清单

只看不删，最安全。先选范围，再一页一页看，看完输 `q` 回菜单。完整清单已经备份到 `repos_list.txt`，里面是全部仓库的名字。

### 5.2 选 2：勾选删除仓库

1. 先选范围（个人 / 组织 / 全部）。
2. 一页一页看清单，看完输 `q`。
3. 输序号勾选要删的，**一次可以选多个**：
   - 输 `1,3,5`：删第 1、3、5 个
   - 输 `1,3,5-8`：删第 1、3、5、6、7、8 个
   - 输 `all`：这个范围里的全部都删
   - 输 `0`：退出，什么都不删
4. 选完会列出你要删的仓库，再问你两次，都是输 `y`：
   - 第一次：`确认清单无误？输入 y 继续` → 输 `y`
   - 第二次：`最后确认：真的要删除这几个仓库？输入 y 确认` → 再输 `y` 才真删
   - 第二次输别的就取消，什么都没删。
5. 删完逐个回显成功还是失败，写进 `deleted_*.log`。

> 不用再一字不差输 DELETE 了，输 `y` 两次就行。但输 `y` 两次就真删了，删完不可恢复，选序号时看准再输。

### 5.3 选 3：移动合并仓库

把 A 仓库整个搬到 B 仓库的子目录下：

1. 输来源仓库完整名，比如 `dj56959566/old-repo`
2. 输目标仓库完整名，比如 `dj56959566/main-repo`
3. 输子目录名，直接回车就用来源仓库名
4. 先演练一遍，确认没问题输 `y` 才真搬
5. 搬完问你要不要删源库，输 `y` 才删

规则：

- 源码（除 `.git`、`.github/workflows` 外）进 `目标/<来源仓库名>/`，子目录已存在会提示改名
- 工作流单独合并到目标 `.github/workflows/`，不进子目录；内容完全相同跳过，内容不同绝不覆盖，会提示改名（回车自动改成 `<名>-<来源库名>.yml`，输“跳过”不合并）
- 只搬文件，不搬 Issues / PR / Release / Star

### 5.4 选 4：归档仓库

先选范围，再输序号勾选，归档代替删除，只读、可恢复，比删除安全。流程和删除一样，也是输 `y` 两次确认，写进 `archived_*.log`。

### 5.5 选 0：退出

什么都没动，直接退出。

## 6. 命令行用法（不用菜单时）

```bash
# 只看清单，不删（先跑这个，最安全）
python3 clean_repos.py --list-only

# 交互式勾选删除（默认模式）
python3 clean_repos.py

# 只扫某个组织 / 某个账号
python3 clean_repos.py --org xxx
python3 clean_repos.py --owner dj56959566

# 只看私有库 / 只看公开库 / 只看已归档库
python3 clean_repos.py --private --list-only
python3 clean_repos.py --public --list-only
python3 clean_repos.py --archived-only --list-only

# 只列含某关键词的仓库
python3 clean_repos.py --keyword clash --list-only

# 从文件批量删（每行一个完整名 owner/repo），非交互需同时加 --yes --force
python3 clean_repos.py --file delete_list.txt --dry-run   # 先演练
python3 clean_repos.py --file delete_list.txt --yes --force

# 不想真删、只想归档（可恢复）：加 --archive，代替删除
python3 clean_repos.py --archive

# 移动合并：把 A 仓库整个搬到 B 仓库的子目录下
python3 clean_repos.py --move dj56959566/old-repo --to dj56959566/main-repo
python3 clean_repos.py --move dj56959566/old-repo --to dj56959566/main-repo --subdir mydir
python3 clean_repos.py --move dj56959566/old-repo --to dj56959566/main-repo --delete-source
python3 clean_repos.py --move dj56959566/old-repo --to dj56959566/main-repo --auto-rename
```

设 Token 的三种办法（命令行模式）：

```bash
# Windows
set GITHUB_TOKEN=ghp_xxxx
# Linux / Mac / Serv00
export GITHUB_TOKEN=ghp_xxxx
# 或者用 gh 登录过：gh auth login，脚本会自动用 gh auth token
```

## 7. 打包与主页发行版

- 工作流文件：仓库里的 `.github/workflows/github-repo-cleaner.yml`
- 脚本在 `gsoft/clean_repos.py`，不在根目录，打包命令用的是 `gsoft/clean_repos.py`
- 去 Actions 页 → Build github-repo-cleaner.exe → Run workflow 手动跑一次，跑完回主页看发行版
- 发行版里放的是压缩包 `github-repo-cleaner-windows.zip`，下载解压得到 exe
- 版本号从 `clean_repos.py` 里的 `VERSION` 自动读，每次改代码升版本，重跑就发对应版本号的新发行版
- 发行版只保留最新 2 个版本，超过的会自动删掉
- Actions 页面里不再放附件，打包文件只在发行版里下载

## 8. 常见问题

| 问题 | 原因和办法 |
|---|---|
| 双击 exe 一闪而过 | 没 Token 就退出了，或者出错了。先按第 3 节准备好 Token 再跑；每步后都要按回车才回菜单 |
| 右键粘贴没反应 | 黑窗口里右键才是粘贴，左键是选中。见第 3.4 节，用回车自动读剪贴板或者 `token.txt` |
| 按 `Ctrl+V` 出来还是刚打的字母 | 剪贴板里当时就只有那个字母，Token 没复制上。回浏览器重新复制完整 Token（`ghp_` 开头的那一长串）再回来按回车 |
| 网址显示乱码方框 | 老版本用的链接格式老黑窗口不支持，v1.5 开始已改回纯文字网址，传 v2.0 覆盖再重打包就没有了 |
| Token 不对，401 | Token 抄错了、过期了，或者不是这个账号的 Token。重新复制完整 Token 再试 |
| 403 | Token 缺权限：删库要 `delete_repo`，扫组织要 `read:org`；组织仓库还要你是该组织的管理员 |
| 404 | 仓库已删 / 不存在，或者 Token 看不到它（私有库要 `repo` 权限） |
| 扫不到组织仓库 | Token 没勾 `read:org`，或者你不是那个组织的成员 |
| 打包报 `clean_repos.py does not exist` | 工作流里打包路径不对。脚本在 `gsoft/` 里，打包命令要是 `gsoft/clean_repos.py` |
| 主页看不到发行版 | 手动跑只出附件不发发行版是旧工作流的问题。新工作流手动跑也发，覆盖 `.github/workflows/github-repo-cleaner.yml` 后重跑一次 |
| 登录用户名密码不对 | GitHub 账号密码输错了，或者那个号没开这个仓库的权限。换个有权限的号登录，不要在聊天里发密码 |
| 翻页提示看不懂 | 看完一页，下面会单独显示“看完了吗？输 q 结束浏览，去勾选”，输 `q` 就去勾选，输 `n` 看下一页 |
| 选范围那页看不清 | v1.8 开始每个范围单独一行、中间空一行、后面还显示有几个仓库，传 v2.0 覆盖再重打包 |
| Defender 误报 | PyInstaller 打包的 exe 常被误报，点“更多信息 → 仍要运行”即可 |

## 9. 安全提醒

- Token 是钥匙，**不要发给别人，不要写进脚本，不要传到 GitHub 仓库里**。启动时现问现用，用完就没了。
- `token.txt` 只放你自己电脑上，用完可以删掉，千万别传到仓库里。
- 删除不可逆，删前看准序号，选完第一次输 `y`、第二次输 `y` 才真删，第二次输别的就能取消。
- 删错了 GitHub 恢复不了，只能从本地备份或者 `repos_list.txt` 里的名字重新找回来。
